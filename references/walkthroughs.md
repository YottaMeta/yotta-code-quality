# 元质复杂场景走查

## 走查 1：小改动发布评审

输入：一个 40 行的服务层改动，修改错误处理并新增一个参数。

1. 先读 diff 与调用点，确认入口和影响面。
2. 按 R2 检查错误分支是否改变语义。
3. 按 R3 检查新增参数是否有默认值与调用方兼容。
4. 按 T1/T3 检查测试是否覆盖新错误分支。
5. 输出 2-3 条高价值发现，附 Iron Law 四段与健康分。

## 走查 2：大型 PR 分层评审

输入：一个 2000 行重构 PR。

1. 只看文件清单与依赖图，先分出入口、领域、基础设施、测试。
2. 对高风险模块做全文评审，低风险机械改动只抽样。
3. 优先检查 R4（耦合）、R5（结构）、R6（命名）。
4. 输出分层结论和必须人工复核的路径。
5. 标注“未全文评审”的范围，不假装全覆盖。

## 走查 3：首屏 UX 专项

输入：一个新页面，功能可用但首屏偏慢。

1. 按 UX1 检查首屏关键路径。
2. 识别阻塞渲染的脚本、字体和图片。
3. 按 R7 检查是否存在不必要的复杂度。
4. 输出可验证的优化建议，如“延迟加载非首屏模块”“压缩首屏图片”。
